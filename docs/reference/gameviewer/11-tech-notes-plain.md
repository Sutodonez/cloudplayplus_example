## 1. 对称型 NAT 的打洞穿透

家里路由器像一道门：出门上网时，路由器给你的包临时贴一张「出门条」（公网地址+端口）。**对称型 NAT** 更严：你连不同的人，它贴的出门条不一样，对方很难猜你下次会从哪个口出来，所以普通「互报地址再对打」经常失败。

GameViewer 大致这样走：

1. 两边先连到同一间「房间」（信令），并拿到 ICE/打洞用的账号口令一类信息。  
2. 用 STUN/公网探测，弄清自己出门条大概什么样；还会往公共 DNS 地址丢 UDP，试防火墙/NAT 松不松。  
3. 专门有一段 **Enhanced Hole Punching**：在已知对方候选地址后，按对称 NAT 的特点去「乱试/对打」UDP（实现对 Cone 的 SymmetricPunch），让双方路由器各自记住「对方那边也在敲门」，中间就可能捅开一条直连。  
4. 直连稳了就尽量 **P2P**；不行再走中继（`force_relay`），并按丢包、延迟、运营商自动换路。

**一句话：** 先互相摸清出门条，再针对「对称 NAT 出门条爱变」做加强互打；打不通就走服务器转发。

**选型提示：** 若目标环境对称 NAT 多、又要低延迟，需要「信令 + STUN + 加强打洞 + 中继兜底」这一整条梯子，而不是只做简单 UDP 互报。

## 2. 老游戏里远程鼠标仍正常

很多老游戏不问「鼠标在屏幕哪」，只问「这一帧相对动了多少」（相对鼠标）。普通远程桌面常注入「跳到屏幕某一点」的**绝对坐标**；游戏按「位移」去理解，幅度就会飞、拧巴。

GameViewer 在被控端不只靠普通「模拟点击到某点」，还准备了更像真鼠标的路径：可在 **普通注入** 和 **虚拟 HID（vhid）** 之间切换，并处理相对报告布局；设置里有「虚拟鼠标开关」一类项。对相对鼠标的游戏，传的是「动了多少」而不是「落在哪」，手感就接近本机。

**一句话：** 按游戏习惯送**相对移动**（必要时走虚拟鼠标设备），避免远程软件那种绝对落点把老游戏搞乱。

**选型提示：** 面向相对鼠标/Raw Input 老游戏时，优先「相对位移 +（可选）虚拟 HID」，不要只靠绝对落点远程桌面方案。
